# Security Policy

## Scope and data

This repository is a portfolio project. **All data is synthetic**: claims, patients, payers
and policy documents are generated by `src/claims_agent/data/seed.py` or hand-written for the
demo. Do not load real protected health information (PHI) into it. The guardrails here are
illustrative heuristics, not a certified de-identification or HIPAA compliance control.

## Reporting a vulnerability

Please open a private security advisory on the GitHub repository
(`Security` tab -> `Report a vulnerability`) rather than a public issue. Include steps to
reproduce and the affected version/commit. You can expect an acknowledgement within a week.

## Handling secrets

- Credentials are read only from environment variables; see `.env.example` (no values).
- `.env` is git-ignored. Never commit API keys or cloud credentials.
- The default `scripted` planner needs no credentials and makes no network calls.

## Built-in safeguards

- PHI fields and PHI-like patterns are redacted from tool outputs before they reach the
  planner, the trace files or the API response.
- Retrieved text matching prompt-injection heuristics is withheld from the planner.
- Tools are allowlisted per agent, arguments are schema-validated, and tool calls are
  budgeted per run.
